Purpose and Design Direction

This catalog maps a powerful archive and packaging capability into focused, reusable skills. The design favors safe handling of untrusted content, predictable outputs, partial and resumable work, high-volume parallel execution, verifiable integrity, and clean handoff to people or downstream agents.

How to Use This Catalog

- Select a narrow skill when one clear operation is needed, such as extracting one entry, creating split volumes, or verifying checksums.

- Compose complementary skills for end-to-end workflows, such as preflight -> quarantine -> extract -> organize -> scan -> verify -> publish.

- Keep orchestration separate from low-level format handling so workers can be replaced or scaled without changing the job contract.

- Require manifests, checkpoints, and validation for large or consequential jobs. Never treat a partially completed extraction as a complete result.

- Use explicit resource and safety limits for nesting depth, file count, expanded size, ratio, path length, runtime, memory, and temporary storage.

Recommended Capability Layers

Control plane: Accept requests, validate policies, plan jobs, schedule work, report progress, and publish results.

Format workers: Perform archive-specific listing, extraction, testing, creation, and recovery through stable adapters.

Safety boundary: Enforce path, link, bomb, malware, credential, isolation, and access-control protections.

Evidence layer: Generate manifests, hashes, logs, lineage, scan results, and completion reports.

Storage layer: Stage inputs, manage temporary data, publish atomically, and apply retention or disposal rules.

1. Core Archive Extraction

1. Skill Name: Universal Archive Extractor

Description: Detect and extract ZIP, ZIP64, 7z, RAR, TAR, GZIP, BZIP2, XZ, Zstandard, LZ4, CAB, ISO, DMG, WIM, and other supported containers through a unified workflow.

2. Skill Name: Format Signature Detector

Description: Identify the real archive or container type from magic bytes and structure, even when extensions are missing, incorrect, duplicated, or intentionally misleading.

3. Skill Name: Single-Item Precision Extractor

Description: List archive contents and extract one selected file or folder without unpacking unrelated data, while preserving its internal path and metadata.

4. Skill Name: Selective Pattern Extractor

Description: Extract entries by name, extension, path, size, date, regular expression, include list, or exclude list.

5. Skill Name: Full-Fidelity Extractor

Description: Extract every valid entry while retaining timestamps, permissions, symbolic links, extended attributes, alternate streams when supported, and source manifests.

6. Skill Name: Nested Archive Unwrapper

Description: Recursively discover and unpack archives inside archives with configurable depth, cycle protection, duplicate detection, and parent-child lineage.

7. Skill Name: Split-Volume Archive Assembler

Description: Recognize and assemble multipart sets such as .001, .z01, split 7z, and multipart RAR before extraction; report missing or inconsistent volumes.

8. Skill Name: Self-Extracting Archive Handler

Description: Inspect common self-extracting executable containers and recover embedded payloads without running untrusted executable code whenever tooling permits.

2. Large-Scale and Incremental Extraction

9. Skill Name: Chunked Extraction Engine

10. Skill Name: Streaming Extractor

11. Skill Name: Entry-by-Entry Extractor

12. Skill Name: Range and Portion Extractor

13. Skill Name: Checkpointed Extraction Runner

14. Skill Name: Low-Disk-Space Extractor

15. Skill Name: Sparse and Huge-File Handler

16. Skill Name: Adaptive Resource Governor

Safe untrusted extraction: Preflight Archive Inspector -> Quarantine Extraction Runner -> Zip-Slip Defense Guard -> Decompression Bomb Detector -> Universal Archive Extractor -> Malware Scan Orchestrator -> Extraction Completeness Auditor -> Transactional Output Publisher.

Very large archive processing: Cost and Resource Estimator -> Chunked Extraction Engine -> Checkpointed Extraction Runner -> Adaptive Resource Governor -> Archive-to-Folder Organizer -> Checksum Verification Engine -> Job Summary Report Generator.

Damaged archive recovery: Preflight Archive Inspector -> Missing Volume Diagnoser -> Corruption Locator -> Damaged Archive Recovery Assistant -> Partial Archive Salvager -> Partial Success Reporter.

Minimum Quality Bar for Future Implementations

- Every job has a unique ID, immutable source fingerprint, explicit parameters, status, and machine-readable result.

- Operations are idempotent where practical and never overwrite existing data silently.

- Large jobs support cancellation, bounded resources, checkpoints, resume, and partial-success reporting.

- Untrusted archives are processed without executing embedded content and with path, link, nesting, count, ratio, and size defenses.

- Created archives are format-tested, checksum-verified, and round-trip checked for important deliveries.

- All outputs preserve provenance through manifests that connect each result to its source archive and entry path.

- Failures identify the smallest affected unit and provide a safe repair or retry path without discarding verified work.

- Final publication is transactional: stage, validate, then atomically expose complete results.
