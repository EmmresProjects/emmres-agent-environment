Catalog Scope

This catalog covers Windows, macOS, Linux, Android, iOS, and cross-platform application development using Flutter, React Native, .NET MAUI, Qt, Tauri, Electron, SwiftUI, Jetpack Compose, Kotlin Multiplatform, Avalonia, Uno Platform, and native stacks.

The intended development environment can be fully air-gapped. Toolchains, SDKs, package registries, emulator images, documentation, symbols, native libraries, test fixtures, and release dependencies are cached, pinned, licensed, and validated before network access is removed.

Store accounts and external services remain optional deployment dependencies. Skills separate offline development and runtime behavior from later signing, notarization, store submission, push delivery, payment processing, or backend operations that inherently require external infrastructure.

Recommended Skill Architecture

Control plane: Selects targets, framework, architecture, toolchains, security profile, packaging route, and acceptance matrix.

Platform packs: Contain the exact SDK, build, signing, device, packaging, and policy steps for Windows, macOS, Linux, Android, and iOS.

Execution skills: Perform deterministic scaffolding, dependency restoration, builds, tests, migrations, packaging, and diagnostics.

Validation skills: Independently test clean builds, offline behavior, security, accessibility, performance, upgrades, recovery, and target devices.

Release skills: Sign, attest, package, submit, deploy, roll back, and preserve reproducible evidence without mixing development secrets into source artifacts.

Core Acceptance Reference

- A clean machine installs the complete local toolchain from the offline bundle with no first-run download.

- Locked dependencies restore from local caches, then debug and release builds succeed with network access blocked.

- The application installs, launches, stores and migrates data, survives restart, handles denied permissions, and preserves user data through upgrade and rollback scenarios.

- Automated unit, integration, UI, accessibility, security, localization, offline, and performance tests pass on representative simulators, emulators, and physical target devices.

- Release artifacts are reproducible where the platform permits, signed with controlled keys, accompanied by checksums, SBOM, license manifest, privacy declarations, and rollback instructions.

- Features that require external infrastructure, such as push delivery, payments, store submission, and remote backend service, degrade clearly when offline and are verified separately in controlled connected environments.

Catalog Design Notes

- Keep platform-independent Skills separate from platform-specific toolchain, permission, signing, and store rules.

- Treat an offline dependency bundle as a release artifact. Pin versions and hashes, collect licenses, and prove restoration on a clean machine with the network blocked.

- Use physical devices for camera, microphone, GPS, Bluetooth, biometrics, background execution, battery, thermal, notification, and store-distributed acceptance tests.

- Never place private signing keys, production secrets, store credentials, or payment credentials inside the catalog or ordinary source repository.

- Freeze one passing end-to-end reference build before expanding features, then rerun affected joins after every toolchain, SDK, database, or dependency update.
