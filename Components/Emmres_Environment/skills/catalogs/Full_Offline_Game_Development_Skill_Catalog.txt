Catalog Scope

This catalog covers Godot, Unity, Unreal Engine, and Roblox Studio workflows plus platform SDKs, gameplay systems, multiplayer, backend readiness, offline AI-assisted asset creation, art, audio, animation, levels, testing, optimization, packaging, stores, rights, and lifecycle operations.

A fully offline pipeline can cover editing, asset creation, local servers, tests, and most desktop, mobile, and web builds when all installers, export templates, SDKs, packages, documentation, models, and licenses are cached in advance. Console SDKs require platform authorization. Roblox publishing and many platform services require connected vendor infrastructure even when local creation and testing are prepared offline.

No document in this package contains engine binaries, console SDKs, proprietary models, store credentials, signing keys, or third-party assets. Those must be acquired and governed separately under their applicable licenses and access agreements.

Recommended Skill Architecture

Production control plane: Selects engine, platforms, game architecture, content budgets, offline tools, licenses, build route, and acceptance matrix.

Engine packs: Contain exact Godot, Unity, Unreal Engine, or Roblox Studio conventions, project structures, exporters, tests, and platform constraints.

Content skills: Create and validate code, scenes, levels, meshes, materials, animation, audio, UI, localization, and accessibility assets.

Runtime skills: Implement gameplay, physics, AI, save data, networking, backend interfaces, anti-cheat, performance, and crash recovery.

Release skills: Reproduce builds, sign and package artifacts, run target-device acceptance, prepare store submissions, and preserve rights and provenance evidence.

Core Acceptance Reference

- A clean machine installs the selected engine, export templates, SDKs, compilers, local package caches, models, and documentation from the offline bundle without hidden downloads.

- The example project opens, imports assets, runs the core gameplay loop, saves and restores progress, accepts keyboard and gamepad input, and produces reproducible target builds with the network blocked.

- Automated gameplay, physics, AI, UI, save, localization, accessibility, performance, packaging, crash recovery, and target-device tests pass against frozen reference cases.

- Every engine, plugin, model, voice, font, mesh, texture, sound, music track, and generated asset has a license and provenance record that permits the intended commercial or noncommercial use and redistribution.

- Online-only services such as publishing, platform authentication, matchmaking, commerce, telemetry, and crash upload are represented by local mocks during offline development and verified separately in authorized connected environments.

- Release artifacts remain within frame-time, memory, storage, loading, network, battery, and thermal budgets for the declared minimum target hardware.

Catalog Design Notes

- Keep engine-neutral design Skills separate from Godot, Unity, Unreal Engine, and Roblox Studio implementation packs.

- Freeze one passing vertical slice that joins input, gameplay, UI, save data, audio, localization, accessibility, build, and installer paths before scaling content production.

- Treat neural models and generated assets as production dependencies. Pin versions, record prompts and settings when useful, verify licenses, and require human art-direction and gameplay checks.

- Use physical devices and authorized development kits for final controller, performance, thermal, network, suspend, store, and platform compliance testing.

- Never bundle proprietary console SDKs, private signing keys, store credentials, or restricted marketplace assets into a general Skill package.
