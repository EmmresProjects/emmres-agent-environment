Comprehensive Skill Catalog

A capability blueprint for an air-gapped 3D production agent, covering installation, modeling, sculpting, texturing, rigging, animation, neural generation, simulation, rendering, interoperability, optimization, validation, licensing, packaging, and recovery.

Catalog edition: November 2026

Purpose and Scope

This document is a planning catalog for future reusable skills. It does not install software or implement the skills. Each entry is scoped so a stronger agent can convert it into a standalone skill or a coordinated module. The intended production environment is fully offline or air-gapped, with reproducible setup, editable source files, explicit licensing, deterministic validation, and clean handoff.

Design Principles for Future Skill Builders

- Use Blender or an equivalent installed DCC through documented, version-pinned adapters rather than undocumented manual state.

- Prefer nondestructive and editable workflows until an approved bake, cache, publish, or delivery step requires flattening.

- Treat scale, units, axes, frame rate, color, naming, paths, and rights as shared contracts across every tool boundary.

- Use deterministic scripts for fragile, repeated, batch, validation, and packaging operations.

- Run clean-state, offline-only, round-trip, regression, and recipient-path tests that can fail.

- Record exact application, add-on, model, driver, device, seed, preset, and asset versions needed to reproduce important outputs.

- Block release on critical geometry, rig, shader, texture, simulation, render, legal, or package-completeness defects.

Recommended Catalog-to-Skill Package

When converting an entry into an executable skill, keep the control plane compact and place repeatable detail in supporting resources:

- SKILL.md: precise trigger description, workflow, decision rules, failure conditions, required validation, and completion behavior.

- agents/ui_metadata.yaml: display name, short description, icon, and brand color.

- scripts/: deterministic offline automation, import-export adapters, batch tools, validators, regression tests, and packaging utilities.

- references/: schemas, naming rules, geometry and texture budgets, compatibility matrices, license guidance, and troubleshooting.

- assets/: permitted templates, presets, test scenes, turntables, reference renders, node groups, materials, and fixtures.

Final Acceptance Standard

A future implementation should be considered complete only when it runs without network access, declares dependencies and rights, preserves editable sources and rollback points, reproduces approved outputs from a clean state, passes structural and visual validation, reports failures clearly, and can be packaged, opened, rendered, exported, and continued by the intended recipient.
