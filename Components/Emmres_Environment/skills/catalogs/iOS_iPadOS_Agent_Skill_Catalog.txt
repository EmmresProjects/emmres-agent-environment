Use and Safety Boundary

- Use this catalog only for applications, devices, accounts, data, services, and assets that the operator owns or is explicitly authorized to inspect, build, modify, test, preserve, migrate, sign, or distribute.

- Preserve original IPA files, archives, profiles, logs, backups, and metadata before any transformation. Distinguish encrypted App Store binaries from unencrypted development artifacts.

- Do not claim installability without valid signing, provisioning, trust, device eligibility, and an observed device test. Simulator success does not prove device behavior.

- A 32-bit-only iOS app cannot run on iOS 11 or later. A genuine 64-bit rebuild requires source or equivalent authorized redevelopment.

- Never bypass Apple ID, Activation Lock, passcodes, biometrics, Secure Enclave, purchases, DRM, device ownership, authentication, or certificate protections.

Appendix C. Standard Skill Contract

Purpose: One narrow operational outcome.

Authorized scope: Application, device, account, team, network, data, service, method, and time boundaries.

Inputs: Artifacts, source, scheme, configuration, signing mode, destination, credentials channel, and expected behavior.

Outputs: Human report, machine JSON, transformed artifact, logs, hashes, and next routing decision.

Dependencies: Linux or macOS host, Xcode, versions, account, device, network, credentials, license, disk, and memory.

Side effects: Files, keychains, profiles, device state, installed apps, network calls, uploads, and cleanup.

Verification: Fixture, clean-state rerun, signature verification, install and launch where relevant, xcresult parsing, and artifact reopen.

Recovery: Preserve last passing output, isolate earliest bad state, make one reversible repair, and rerun affected checks.

Safety gate: Require explicit approval before destructive device actions, signing with protected identities, uploads, data extraction, or scope expansion.

Appendix E. Completion Rules

- A capability is not complete because a command exists. It must pass a version check and the smallest lawful fixture that proves its main function.

- Every transformation preserves the original, records exact inputs and outputs, and validates the artifact consumed by the next stage.

- Every build claim names Xcode, SDK, scheme, configuration, destination, architecture, signing mode, and observed result.

- Every signing claim verifies nested components, entitlements, profile, identity, team, bundle identifiers, dates, and device eligibility.

- Every compatibility claim distinguishes Simulator from physical hardware and local application behavior from remote service availability.

- Every partial result states what passed, what is blocked, the exact host, account, device, license, or network dependency, and the safest continuation point.
