SHARED 2D AND 3D
ANIMATION PRODUCTION
Comprehensive Skill Catalog

A shared capability blueprint for offline animation production, from story development and version control through voice, sound, music, color, rendering, quality control, rights, playback, and delivery.

Catalog edition: November 2026

Purpose and Scope

This catalog defines reusable capabilities shared by 2D and 3D animation pipelines. It is a planning catalog, not a package of implemented skills. Every entry is scoped so a stronger agent can later convert the entry into an independent skill or a coordinated module. The design assumes offline or air-gapped execution, editable sources, reproducible outputs, explicit rights, and validation that can fail.

Catalog Design Principles

- Use one source of truth for project standards, names, versions, approvals, rights, and delivery requirements.

- Prefer deterministic scripts and manifests for fragile, repeated, or high-volume operations.

- Preserve editable sources, approved references, rollback points, and exact provenance.

- Test from clean state and with network access disabled. Hidden cloud dependencies are production defects.

- Validate technical structure, visual and audio quality, accessibility, playback, and handoff separately.

- Keep shared skills application-neutral, with adapters for specific DCC, editorial, audio, and finishing tools.

- Block final release when critical QC, rights, approval, or package-completeness requirements fail.

Recommended Implementation Pattern

When an entry is converted into a real skill, keep the core instructions short and place repeatable detail in supporting resources:

- SKILL.md: precise trigger description, workflow, decision rules, required validations, and completion behavior.

- agents/ui_metadata.yaml: human-readable display name, short description, icon, and brand color.

- scripts/: deterministic local automation, validators, converters, manifests, and smoke tests.

- references/: standards, schemas, naming rules, compatibility matrices, delivery specifications, and troubleshooting.

- assets/: permitted templates, presets, test media, sample projects, fonts, icons, and reference fixtures.

Shared Production Acceptance Standard

A future skill implementation is complete only when it works without network access, declares dependencies and rights, preserves editability and rollback, produces reproducible outputs, validates its result through the real recipient path, records versions and provenance, handles expected failures safely, and can be installed and rerun from a clean offline state.
