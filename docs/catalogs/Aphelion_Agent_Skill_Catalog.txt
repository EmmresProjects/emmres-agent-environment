  ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  This catalog converts the source audit into a broad set of reusable skill concepts. It includes the audit’s source-aware document and slide engineering needs, then expands into research, coding, web, data, media, automation, security, education, business, and delivery workflows. Each entry is a catalog specification, not an implemented skill package.

34 categories | 408 skill concepts

How to Use This Catalog

- Choose one catalog entry when its workflow, inputs, and output contract are narrow enough to be repeatable.

- Keep each implemented SKILL.md concise. Move detailed standards, schemas, examples, and provider notes into references.

- Use scripts for deterministic or fragile operations, and assets for editable templates, brand files, or fixtures.

- Define trigger conditions, accepted inputs, output formats, safety boundaries, verification checks, and failure behavior.

- Prefer minimal, reversible changes to provided files. Preserve unsupported objects instead of flattening or silently replacing them.

- Validate the final artifact through the recipient’s real use path, including rendering, accessibility, package integrity, and clean-state reproduction.

Source Foundation

The source audit emphasizes read-first inspection, object-level edits, reuse of existing structures, protected-scope enforcement, native editability, visual and structural verification, failure isolation, and clean handoff. Those principles are carried throughout this catalog and expanded far beyond presentation work.

Implementation Standard for Every Future Skill

Trigger precision: State exactly when the skill should activate and when a different skill should be preferred.

Input contract: List accepted files, schemas, connectors, required fields, optional fields, and size limits.

Output contract: Define filenames, formats, folder structure, editability, metadata, and delivery expectations.

Source-first behavior: Inspect provided material before generating replacements; reuse existing objects and conventions when safe.

Scope control: Use allowlists, denylists, protected items, approvals, and irreversible-action gates.

Verification: Run structural, semantic, visual, accessibility, integrity, and clean-state checks that can fail.

Recovery: Preserve the last passing state, isolate the earliest bad state, repair the smallest cause, and rerun affected checks.

Provenance: Record where material came from, which transformations were applied, and which claims remain uncertain.

Security and privacy: Minimize data exposure, avoid secrets in logs, respect permissions, and scrub sensitive metadata when required.

Handoff: Return usable artifacts, not process residue; include editable sources and reproducible instructions when appropriate.
