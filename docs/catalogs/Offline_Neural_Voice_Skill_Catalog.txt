Catalog Scope

This catalog covers the complete offline neural voice lifecycle: licensed model acquisition, air-gapped installation, text and phoneme processing, expressive inference, audio mastering, quality assurance, sandbox operation, safety, fallback behavior, integration, release governance, and the final greeting acceptance scenario.

Every proposed capability is designed around four non-negotiable properties: local execution, CPU compatibility, no required API key, and explicit verification. The catalog intentionally separates small capabilities so an agent can invoke only the minimum tools needed for a task.

The catalog does not bundle model weights, voices, or third-party binaries. Those artifacts must be selected later based on license, redistribution rights, package limits, target CPU, and voice-consent requirements.

Recommended Skill Architecture

Control-plane skill: Routes requests, selects a voice preset and model, enforces rights and safety gates, and coordinates synthesis, mastering, validation, and packaging.

Execution skills: Perform deterministic operations such as normalization, phonemization, ONNX inference, WAV or MP3 export, and quality measurement.

Reference skills: Provide versioned model cards, compatibility matrices, pronunciation lexicons, licenses, and troubleshooting rules without overloading the primary instructions.

Validation skills: Independently test transcript accuracy, duration, loudness, true peak, decoding, offline behavior, and regression against known-good samples.

Fallback skills: Recover from model, memory, or compatibility failures while preserving disclosure, quality thresholds, and user control.

Acceptance Reference Case

Canonical text: “Greetings, friends! Welcome to my video.”

- Voice: natural male-presenting English voice with a 30s age style.

- Delivery: warm, friendly, expressive, and conversational.

- Prosody: a brief pause after “friends” and clear emphasis on “Welcome”.

- Integrity: no robotic sound, buzzing, missing words, repeated words, or cut-off phonemes.

- Duration: 2.5 to 4.0 seconds, measured on the final mastered file.

- Peak: at or below -1 dBFS; integrated loudness targeted near -14 LUFS with the measurement method recorded.

- Formats: playable PCM WAV; optional high-quality MP3 that decodes cleanly.

- Environment: succeeds with internet disabled, no API key, no GPU, and no first-run download.

- Evidence: transcript comparison, audio metrics, model and voice versions, checksums, preset version, and pass or fail report.

Catalog Design Notes

- Use one responsibility per Skill wherever practical. Keep the coordinating Skill compact and move detailed rules into references.

- Pin model, voice, tokenizer, runtime, and preset versions together. A voice model is not interchangeable with every tokenizer or vocoder.

- Treat listening tests and automated metrics as complementary. Transcript accuracy and loudness compliance do not prove naturalness.

- Never distribute weights, embeddings, native libraries, or voices until redistribution permission is documented.

- Disable weak or robotic engines by default. If used as an emergency fallback, disclose the downgrade before synthesis and label the output.

- Require clean-sandbox and network-blocked tests before calling a package fully offline.
