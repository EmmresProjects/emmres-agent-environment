Purpose

This catalog defines a broad, composable library of proposed agent skills. It is a design inventory, not a package of implemented skills. Each entry can later become an independent Skill with its own triggering description, instructions, scripts, references, assets, tests, and safety boundaries.

Catalog Design Principles

- Execution first: every skill should produce observable work, artifacts, or decisions rather than stop at planning.

- Proof before completion: success requires exit codes, tests, rendered outputs, structural checks, or other direct evidence appropriate to the task.

- Safe by default: privileged, destructive, irreversible, costly, or production actions require explicit scope and protective controls.

- Recoverable operation: long-running work should support bounded retries, checkpoints, cancellation, cleanup, and partial-result recovery.

- Composable interfaces: skills should exchange clear inputs, outputs, state, errors, and artifacts so they can form reliable pipelines.

- Cross-platform awareness: command skills should account for Windows, Linux, macOS, containers, remote hosts, and shell dialect differences.

- Context efficiency: detailed references and scripts should load only when the active task requires them.

How to Use the Catalog

1.  Start with a narrow skill that owns one repeatable responsibility.

2.  Combine a planner or router with execution, safety, observability, verification, and handoff skills for high-risk workflows.

3.  Give each future skill a precise trigger description and keep its core instructions compact.

4.  Place deterministic or fragile operations in tested scripts; place detailed standards and variants in references.

5.  Validate each implemented skill against normal, boundary, failure, recovery, repeated-use, and clean-state scenarios.

1. Command, Shell, and Execution Control

Scope: Reusable capabilities in this domain, designed to be independently implementable and composable with other skills.

1. Skill Name: Ultimae Commander

Description: Act as the top-level command authority for complex execution plans. Select shells, establish working directories and environment state, sequence dependent commands, preserve successful outputs, and stop or recover safely when a command violates its expected contract.

2. Skill Name: Executor

Description: Turn an approved plan into concrete tool calls and commands. Track inputs, outputs, exit codes, side effects, artifacts, and completion checks so execution finishes with usable results rather than a partial run.

3. Skill Name: Basher

Description: Author and run robust Bash workflows using strict mode, quoting, traps, functions, pipelines, process substitution, redirection, and portable fallbacks. Detect shell differences and avoid destructive wildcard or expansion errors.

4. Skill Name: Runner

Description: Run scripts, binaries, tests, builds, and data jobs in the correct runtime. Resolve entry points, arguments, permissions, interpreters, dependencies, logs, and output locations before declaring success.

5. Skill Name: Action

Description: Convert a natural-language objective into the smallest safe executable action, then validate the observed outcome. Prefer reversible steps, explicit scope, and direct completion criteria.

6. Skill Name: Command Router

Description: Choose among CMD, PowerShell, Bash, Zsh, Python, Node.js, task runners, package scripts, containers, or native applications based on the operating system, task, and available interfaces.

7. Skill Name: Shell Dialect Adapter

Description: Translate commands across Windows CMD, PowerShell, POSIX sh, Bash, and Zsh while preserving quoting, paths, environment variables, pipes, error behavior, and return-code semantics.

8. Skill Name: Process Supervisor

Description: Start, monitor, pause, resume, terminate, and reap foreground or background processes. Capture process identifiers, detect orphaned work, and apply escalating shutdown from graceful stop to forced termination.

9. Skill Name: Exit-Code Interpreter

Description: Map return codes, signals, stderr patterns, and partial output to actionable states such as success, retryable failure, configuration fault, dependency fault, permission fault, or user input error.

10. Skill Name: Execution Contract Enforcer

Description: Require every command to define expected inputs, permitted side effects, success signals, failure signals, output paths, and cleanup behavior before it is used in a critical workflow.

2. Timeouts, Scheduling, and Long-Running Work

Scope: Reusable capabilities in this domain, designed to be independently implementable and composable with other skills.

1. Skill Name: Adaptive Timeout Manager

Description: Set timeouts from workload type, input size, historical duration, and stage criticality. Extend only when progress signals remain healthy, and terminate stalled work with preserved diagnostics.

2. Skill Name: Deadline Budgeter

Description: Allocate an overall time budget across setup, execution, verification, repair, export, and cleanup. Rebalance remaining time when a stage finishes early or consumes more than planned.

3. Skill Name: Heartbeat Monitor

Description: Require periodic progress markers from long-running jobs. Distinguish slow progress from deadlock by monitoring timestamps, CPU, I/O, output growth, and child-process state.

4. Skill Name: Checkpoint Resumer

Description: Add checkpoints to long jobs so interrupted work can resume from the last valid state instead of restarting. Verify checkpoint compatibility with code, inputs, and configuration.

5. Skill Name: Scheduled Task Builder

Description: Create repeatable schedules using cron, systemd timers, Windows Task Scheduler, CI schedules, or queue triggers. Include timezone, missed-run, overlap, retry, and notification rules.

6. Skill Name: Backoff Controller

Description: Apply bounded exponential backoff with jitter for transient failures. Respect service rate limits and stop retrying on deterministic faults or when the retry budget is exhausted.

7. Skill Name: Long Job Detacher

Description: Run durable work with nohup, tmux, screen, systemd-run, job queues, or platform-native background services while preserving logs, environment state, and a reliable reconnection path.

8. Skill Name: Stall Detector

Description: Detect jobs that are alive but not advancing through output stagnation, unchanged checkpoints, blocked system calls, queue inactivity, or resource starvation.

9. Skill Name: Runtime Estimator

Description: Estimate duration from input volume, concurrency, throughput, warm-up, network latency, and verification cost. Update the estimate from observed progress without presenting guesses as guarantees.

10. Skill Name: Graceful Cancellation

Description: Support cooperative cancellation tokens, signal handling, transaction rollback, temporary-file cleanup, and resumable state so interrupted work does not corrupt outputs.

6. Skill Name: Concurrency Guard

7. Skill Name: Pipeline Stage Manager

8. Skill Name: Multi-Agent Task Dispatcher

9. Skill Name: Speculative Execution Controller

Description: Run alternative approaches only when the benefit exceeds cost. Select the first verified result, cancel redundant work, and retain diagnostics from losing paths when useful.

10. Skill Name: Batch Window Optimizer

Description: Choose batch sizes and execution windows that balance throughput, memory, latency, API quotas, and recovery cost. Avoid producing batches too large to retry safely.

Implementation Standards for Future Skills

- Name skills with short lowercase hyphenated identifiers when packaged, while retaining human-readable display names.

- Define what triggers the skill, what is outside scope, required inputs, produced outputs, permitted side effects, and completion checks.

- Use parameterized scripts for fragile command logic and test representative paths before packaging.

- Never embed secrets. Use environment variables, secret stores, or connected credentials with least privilege.

- Require explicit safeguards for destructive commands, privilege escalation, production changes, billing impact, and broad data access.

- Preserve logs, diagnostics, and valid partial artifacts when a run fails, but remove temporary or sensitive residue from delivery packages.

- Provide a clean handoff: exact files, paths, open or run instructions, prerequisites, and known limitations.
