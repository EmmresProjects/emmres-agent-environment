AGENT SKILL
CATALOG

Universal Application Creation, Software Engineering, and Delivery

30 categories • 244 proposed skills

Purpose
A comprehensive catalog for designing a modular agent that can plan, build, read, repair, transform, test, package, and maintain applications in user-specified languages, frameworks, builders, IDEs, runtimes, and target formats.

  -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  Design principle: Use focused, composable skills rather than one unlimited “knows everything” skill. Each implementation should resolve the requested version, read authoritative documentation when needed, work from actual files and tools, state capability boundaries, and verify outputs before claiming success.
  -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

  -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

How to Use This Catalog

- Select the smallest set of skills that covers the user’s request. Route by platform, language, framework, version, artifact type, and delivery target.

- Implement each catalog item as a separate reusable skill or as a focused reference module under a broader skill. Keep trigger descriptions precise to prevent unrelated activation.

- Do not bundle every historical and current document into a skill. Store compact version maps and retrieve authoritative documentation for the exact version when the task requires it.

- Require executable checks for code and artifact claims: build, test, lint, render, package, reopen, or run through the recipient’s path whenever available.

- Compose app-building work through an app-factory workflow: requirements → architecture → implementation → tests → security → documentation → packaging → release readiness.

Recommended Catalog Fields for Future Skill Creation

  --------------------------------------------------------------------------------------------------------------------------------------------------------
  Field                               What to capture
  ----------------------------------- --------------------------------------------------------------------------------------------------------------------
  Skill name                          Short, specific, lowercase package name and a readable display name.

  Trigger description                 What the skill does and the exact requests, files, platforms, or situations that should invoke it.

  Inputs                              Required files, repository, language, version, target platform, credentials, data, and constraints.

  Outputs                             Exact artifact types, folder structure, source, tests, documentation, packages, and reports.

  Toolchain                           Compilers, SDKs, IDEs, package managers, builders, emulators, devices, and external services.

  Version policy                      Supported versions, documentation source, compatibility matrix, migration rules, and forbidden version mixing.

  Workflow                            Ordered build steps, decision points, fallback paths, and handoffs to other skills.

  Verification                        Build, test, security, accessibility, performance, packaging, visual, and recipient-path checks.

  Boundaries                          Unavailable hardware, credentials, licenses, network access, store submission, or actions requiring user approval.
  --------------------------------------------------------------------------------------------------------------------------------------------------------

3. Build: Requested language, framework, builder, database, and integration skills

6. Operate: Observability Instrumentation Engineer + Site Reliability Engineer + Maintenance and Upgrade Planner

Appendix B: Non-Negotiable Execution Rules

- Never claim a project builds, runs, passes tests, or is store-ready unless the corresponding check was actually completed.

- Never mix syntax, APIs, build files, or documentation from incompatible versions. Resolve the target version first.

- Preserve user code and edits. Make the smallest correct change and include regression coverage for repaired defects.

- Use real project files and environments when supplied. Do not replace missing inputs with invented production data.

- Return clean, editable source and exact build or run instructions. Include only requested artifacts in the final package.

- Treat security, privacy, accessibility, licensing, and platform policy as design constraints, not optional final checks.
