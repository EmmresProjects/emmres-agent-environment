How to Use This Catalog

- Treat every entry as an independent candidate skill or as a component that a future orchestrator may combine with adjacent skills.

- When implementing a skill, define triggers, exclusions, exact inputs, outputs, permissions, account dependencies, failure meanings, fallback routes, and tests.

- Because Google Slides changes by account, edition, browser, language, administrator policy, and staged rollout, implemented skills should detect capability availability before acting.

- Prefer native editable Slides objects and reversible workflows. Use named versions before risky edits and verify real recipient access after sharing or publishing.
