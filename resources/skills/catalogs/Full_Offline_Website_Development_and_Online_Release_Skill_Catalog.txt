Catalog Scope

This catalog covers local runtimes, offline package caches, major frameworks, responsive frontend development, backends, databases, authentication, forms, uploads, commerce, search, CMS, media optimization, testing, accessibility, performance, SEO, privacy, security, hosting, deployment, monitoring, backup, and incident recovery.

Offline development means the runtime, framework packages, browser binaries, documentation, fixtures, fonts, media tools, database tools, and build dependencies are pre-cached and tested with network access blocked. Online release still requires approved infrastructure such as a domain, DNS, TLS, hosting, email or payment services, and production credentials.

No package contains active credentials, private keys, paid fonts, proprietary browser distributions, commercial service accounts, or production data. Those assets must be acquired and governed separately.

Recommended Skill Architecture

Control-plane skill: Selects site architecture, framework, browser support, backend, data stores, accessibility target, security profile, hosting route, and acceptance matrix.

Framework packs: Contain exact conventions, scaffolds, build commands, routing, rendering, testing, and deployment rules for HTML, React, Next.js, Vue, Nuxt, Svelte, Astro, and equivalent stacks.

Execution skills: Build frontend and backend features, optimize media, migrate data, run browsers, create production bundles, and deploy immutable artifacts.

Assurance skills: Independently test WCAG 2.2 AA, Core Web Vitals, security, privacy, SEO, cross-browser behavior, backups, rollback, and production journeys.

Operations skills: Manage domains, TLS, DNS, hosting, CDN, secrets, monitoring, incidents, maintenance, recovery, and lifecycle updates.

Core Acceptance Reference

- A clean machine installs the selected runtime, package cache, framework, browser binaries, database tools, media tools, and documentation from the offline bundle with no first-run download.

- Locked dependencies restore locally, unit and integration tests pass, Chromium, Firefox, and WebKit journeys succeed, and a reproducible production build completes with the network blocked.

- The deployed site resolves through managed DNS, presents valid HTTPS, applies security headers and rate limits, exposes no client-side secrets, and passes critical forms, authentication, email, payment, search, CMS, and migration journeys that are in scope.

- Representative pages pass WCAG 2.2 AA manual and automated checks plus defined Lighthouse and Core Web Vitals budgets on desktop and low-end mobile profiles.

- SEO metadata, canonical URLs, sitemap, robots.txt, structured data, Open Graph previews, localized routes, analytics consent, cookie preferences, error monitoring, uptime checks, backups, restoration, and rollback are validated.

- Production credentials are isolated in approved stores and release evidence records the source revision, lockfiles, build manifest, checksums, environment, deployment, tests, and rollback point.

Catalog Design Notes

- Keep framework-neutral requirements separate from React, Next.js, Vue, Nuxt, Svelte, Astro, and backend implementation packs.

- Freeze a passing end-to-end reference route that joins UI, API, database, authentication, validation, accessibility, build, deployment, monitoring, and rollback before expanding the site.

- Treat offline dependency caches and installed browser binaries as versioned release inputs. Prove restoration and test execution in a clean, network-blocked environment.

- Do not consider an automated accessibility or Lighthouse score sufficient by itself. Preserve manual keyboard, screen reader, zoom, reflow, content, and real-user review where appropriate.

- Separate offline development from online service requirements. Email delivery, payments, external analytics, domain control, public TLS, and production monitoring must be validated in authorized connected environments.
