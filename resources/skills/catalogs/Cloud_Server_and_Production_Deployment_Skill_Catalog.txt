Catalog Scope

This catalog covers public cloud, private cloud, hybrid infrastructure, virtual machines, containers, Kubernetes, serverless, databases, storage, networking, DNS, TLS, CI/CD, observability, security, incident response, backup, disaster recovery, privacy, production testing, and lifecycle operations.

Provider-specific entries include Amazon Web Services, Microsoft Azure, Google Cloud, Oracle Cloud, Cloudflare, DigitalOcean, and common self-hosted tools. A coordinating Skill should select only the provider and service surface required by the target deployment.

No catalog entry contains cloud credentials, signing keys, private certificates, production data, or active account identifiers. Those secrets must remain in approved vaults and be accessed through short-lived, least-privilege identities.

Recommended Skill Architecture

Cloud foundation control plane: Selects provider, accounts, regions, network boundaries, identity model, cost limits, and recovery objectives.

Platform execution skills: Provision compute, containers, Kubernetes, serverless, databases, storage, DNS, TLS, and traffic services through reviewed infrastructure code.

Delivery skills: Build, attest, promote, deploy, verify, and roll back immutable artifacts through hardened CI/CD pipelines.

Operations skills: Monitor golden signals, aggregate logs and traces, route alerts, coordinate incidents, and maintain runbooks and ownership.

Assurance skills: Independently test security, privacy, backup restoration, disaster recovery, load, failover, and production acceptance before go-live.

Core Production Acceptance Reference

- Infrastructure plans are reviewed, policy-checked, and applied through versioned automation with remote encrypted state, locking, backups, and drift detection.

- Production endpoints resolve through managed DNS, present valid TLS, withstand expected load, enforce WAF and rate-limit policies, and expose no unintended public services.

- Applications, databases, queues, caches, storage, and secrets pass connectivity, authentication, encryption, backup, restoration, failover, and rollback tests.

- Monitoring covers latency, traffic, errors, saturation, business health, logs, traces, uptime, certificate expiry, security events, and backup failures with tested alert delivery.

- Recovery point and recovery time objectives are documented and proven through restoration and regional failover drills, not assumed from product marketing.

- Production credentials are short-lived where possible, deployment and code-signing credentials are isolated, and emergency access is logged, reviewed, and regularly tested.

Catalog Design Notes

- Keep provider-neutral control Skills separate from AWS, Azure, Google Cloud, Oracle Cloud, Cloudflare, and self-hosted implementation packs.

- Prefer immutable artifacts and reviewed infrastructure code. Do not repair production by undocumented console changes.

- Treat backup success as incomplete until the target data and full environment have been restored and validated against defined recovery objectives.

- Separate monitoring from alerting. Collect useful signals first, then alert only on conditions that require timely human or automated action.

- Make cost, security, privacy, reliability, and rollback requirements part of the deployment interface rather than post-launch cleanup.
