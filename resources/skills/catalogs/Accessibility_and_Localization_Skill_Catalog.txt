Catalog Scope

This catalog covers accessibility standards, assistive technology, keyboard and voice input, visual and cognitive access, accessible media and documents, localization architecture, translation assets, Filipino and English review, right-to-left support, font coverage, pseudolocalization, human research, automated quality gates, and lifecycle operations.

WCAG 2.2 Level AA is the main web target. Related entries also support WAI-ARIA patterns, PDF/UA, EPUB Accessibility, EN 301 549, Section 508, VPAT reporting, mobile accessibility APIs, Unicode, CLDR, ICU, TMX, TBX, and Multidimensional Quality Metrics where relevant.

Automated checks do not replace disabled-user testing, assistive-technology testing, qualified linguistic review, or jurisdiction-specific legal advice. Skills should route to those reviews when a decision cannot be validated automatically.

Recommended Catalog Architecture

Standards control plane: Routes each artifact to the applicable accessibility criteria, locale rules, test environments, and human review gates.

Automated execution skills: Run deterministic scans, formatting checks, pseudolocalization, visual comparisons, metadata checks, and CI gates.

Human validation skills: Coordinate disabled-user testing, assistive-technology review, translator and in-country review, and issue prioritization.

Language asset skills: Maintain translation memories, termbases, style guides, locale profiles, font coverage, and approved terminology.

Evidence and reporting skills: Preserve reproducible findings, criterion mappings, screenshots, transcripts, locale versions, remediation status, and release decisions.

Core Acceptance Reference

- Web: representative journeys pass WCAG 2.2 AA automated checks plus manual keyboard, focus, zoom, reflow, screen reader, and human accessibility review.

- Documents: Word, Excel, PowerPoint, and PDF outputs preserve headings, reading order, tables, links, language metadata, alt text, contrast, and keyboard or screen reader usability.

- Media: captions are accurate, synchronized, readable, and identify meaningful speakers and sounds; audio description is supplied when important visual information is otherwise unavailable.

- Localization: no hard-coded or untranslated strings, broken placeholders, truncation, glyph loss, date or number errors, bidirectional defects, or locale fallback failures.

- Filipino and English: terminology, grammar, tone, cultural context, Philippine formats, and accessibility language receive qualified bilingual human review.

- Human validation: disabled users and target-language reviewers test representative high-risk journeys before release, with accommodations and privacy protections.

- Evidence: every failure records the artifact, environment, assistive technology or locale, repeatable steps, applicable rule, severity, remediation owner, and retest result.

Catalog Design Notes

- Keep each Skill narrowly scoped. Let a coordinating Skill assemble only the checks required for the artifact, platform, audience, and locale.

- Use automation for breadth and repeatability, then use manual and human testing for behavior, comprehension, natural language, and real assistive-technology outcomes.

- Pin browser, operating system, assistive technology, locale data, font, translation memory, termbase, and rule-set versions in every reproducible test.

- Treat Filipino, Tagalog, Philippine English, and regional Philippine languages as explicit language or locale decisions rather than interchangeable labels.

- Never claim conformance from an automated score alone. Preserve unresolved exceptions and the conditions under which each result was observed.
