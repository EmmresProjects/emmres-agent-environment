Catalog Purpose

This catalog defines reusable capabilities for full offline agents and automation. It covers local models, local knowledge, durable state, tool execution, orchestration, security, reliability, evaluation, operations, and clean-state recovery. It is a catalog only and does not claim that the listed skills are implemented.

Offline Design Principles

- No internet dependency during normal operation.

- Every external package, model, dataset, and update enters through a controlled and verifiable import path.

- Least privilege, explicit approvals, provenance, local audit, and bounded resources apply to all agents and tools.

- Passing behavior must be reproducible from a clean state and recoverable after interruption.

- Human operators retain clear visibility, correction, cancellation, rollback, and emergency-stop controls.

Appendix: Recommended Executable Skill Contract

When a catalog entry becomes an executable skill, define the following contract so it can be tested, governed, repaired, and reused offline.

  -------------------------------------------------------------------------------------------------------------------
  Field                               Definition
  ----------------------------------- -------------------------------------------------------------------------------
  Purpose                             Exact outcome and non-goals.

  Triggers                            Requests, events, schedules, files, or state changes that activate it.

  Inputs                              Types, schemas, limits, classifications, and prerequisites.

  Outputs                             Artifacts, state changes, evidence, and failure forms.

  Local Dependencies                  Models, packages, runtimes, datasets, devices, and operating-system features.

  Permissions                         Files, tools, data, identities, secrets, devices, and network scopes.

  Resource Budgets                    CPU, RAM, VRAM, disk, time, concurrency, and queue limits.

  Procedure                           Ordered checkpoints, joins, retries, approvals, and stop conditions.

  Validation                          Schema, meaning, security, presentation, performance, and clean-state checks.

  Recovery                            Checkpoint, rollback, compensation, replay, and operator handoff.

  Audit and Provenance                Events, sources, versions, decisions, approvals, and artifact lineage.

  Test Fixtures                       Normal, boundary, adversarial, failure, recovery, and regression cases.

  Versioning                          Compatibility, migrations, deprecation, and rollback rules.
  -------------------------------------------------------------------------------------------------------------------
